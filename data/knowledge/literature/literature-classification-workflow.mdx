文献管理的目标不是把PDF摆整齐，而是让你在写某个观点时，能迅速回答“哪几篇文献提供了什么证据”。最实用的结构通常只有三层：题录库、主题分类和证据表。

## 先建立统一题录库

无论使用Zotero、NoteExpress、EndNote还是学校推荐工具，都应先建立一个主库。每条记录至少核对：作者、年份、题名、期刊或出版社、卷期页码、DOI以及附件。

Zotero官方将其定位为收集、组织、引用和共享研究资料的文献管理器，并支持浏览器连接器。使用任何工具时都不要完全相信自动抓取：中文作者名、学位论文类型、网页日期和大小写经常需要人工核对。

## 不要按“已下载”和“未下载”分类

这种分类只能反映文件状态，不能支持写作。更有效的方法是按研究问题分类，例如：

- 理论基础
- 核心关系
- 变量测量
- 识别方法
- 机制解释
- 异质性与边界条件
- 反对证据或不一致结论

同一篇文献可以拥有多个标签，不必强迫它只能进入一个文件夹。

## 建立三级阅读优先级

不是所有搜索结果都值得逐字精读：

1. **A类核心文献**：直接决定理论、变量或识别设计，需要全文精读。
2. **B类相关文献**：用于比较情境、补充机制或写综述，重点阅读摘要、理论和结果。
3. **C类背景文献**：只提供政策或行业背景，保留题录和使用位置即可。

优先级不是质量排名，而是与当前研究问题的关系。高水平但不相关的文章也可能只是C类。

## 证据表应该记录什么

建议使用表格记录以下字段：

| 字段       | 要回答的问题                     |
| ---------- | -------------------------------- |
| 研究问题   | 作者真正要解释什么               |
| 理论机制   | 为什么会产生该关系               |
| 样本与时期 | 证据来自哪里、能推广到哪里       |
| 核心变量   | 如何测量、方向如何解释           |
| 识别方法   | 相关关系还是因果识别             |
| 主要结论   | 方向、量级和适用条件             |
| 局限       | 哪些问题仍未解决                 |
| 对本文用途 | 放在综述、假设、变量还是方法章节 |

“作者认为很重要”不是有效笔记。应写出可以核对的结论、页码和使用位置。

## PDF与附件怎么命名

如果文献管理软件已经能通过元数据检索，不需要建立几十层文件夹。独立保存PDF时，可统一使用：

```text
年份_第一作者_题名关键词.pdf
```

不要只用“1.pdf”“最终版.pdf”或浏览器随机文件名。扫描版资料应补充来源和页码说明。

## 如何从证据表写成文献综述

先按争论或问题聚类，而不是按作者逐篇排列。例如：第一组研究认为数字化通过信息效率促进创新；第二组强调融资渠道；第三组发现作用取决于企业规模。每一段都应包含“共同观点—证据差异—尚未解决的问题”。

引文追溯可以补齐理论源头和新研究，具体见[经典文献与最新研究追溯方法](/literature/citation-tracing)。综述结构形成后，再回到[引言五段式功能结构](/writing/introduction-five-functions)检查缺口是否真的支持研究问题。

## 每周维护一次就够

设置固定流程：导入题录、去重、核对元数据、添加标签、填写证据表、备份文献库。不要边写正文边临时整理全部PDF。稳定的小流程比复杂分类体系更容易坚持。
