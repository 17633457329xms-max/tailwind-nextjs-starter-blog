# 正式上线部署手册（个人站、国内 SEO 优先）

> 适用项目：`tailwind-nextjs-starter-blog`  
> 目标：以个人可承受的预算和维护精力，获得稳定的中国大陆访问体验、可持续收录与可回滚的上线流程。  
> 推荐定位：研究方法教学、选题诊断、写作反馈、论文润色优化一对一定制。公开页面不使用“代写、包过、保证毕业”等高风险表达。

## 1. 先给结论：采用这一套

**阿里云中国大陆轻量应用服务器 + 个人 ICP 备案 + Ubuntu 24.04 LTS + Node.js 20 LTS + Yarn + PM2 + Nginx + 免费 HTTPS + 百度统计 + 百度/必应站长平台。**

这套方案不依赖复杂的容器、Kubernetes、付费海外托管或多人运维；对当前 Next.js 项目兼容性最好，能保留动态文章路由、`sitemap.xml`、结构化数据和咨询接口。国内 SEO 的基础不是“买更贵的服务器”，而是：大陆可稳定访问、页面可抓取、URL 长期不变、持续发布有用内容并主动提交收录。

### 推荐配置与预算边界

| 项目 | 推荐 | 不建议 | 原因 |
| --- | --- | --- | --- |
| 服务器 | **阿里云轻量应用服务器，中国大陆地域** | 腾讯云 Lighthouse、海外免费托管作为主站 | 个人站优先选择阿里云：域名、备案、轻量服务器、SSL、CDN 和对象存储可在一个控制台完成，少一个账号和迁移环节 |
| 最低规格 | **2 核 4 GB 内存、60 GB SSD、5 Mbps 带宽** | 1 核 1 GB | Next.js 构建与后续统计服务需要内存余量 |
| 系统 | Ubuntu 24.04 LTS | Windows Server | 文档多、维护成本低 |
| 域名 | **1 个主 `.com` 域名，不带 `www`** | 同时运营多个主域名 | `https://主域名.com` 更短、更适合视频口播和二维码；`www` 永久 301 到它 |
| DNS | **阿里云 DNS** | 把中国主站完全依赖境外 DNS/CDN | 与服务器、备案在一个账户，故障排查最少 |
| CDN | **首月不开；月访问超过 1 万且页面加载明显变慢时，再开阿里云 CDN** | 一开始购买大量增值服务 | 初期内容、收录和稳定性比 CDN 更重要 |
| 统计 | **百度统计先行；第 3 个月再决定是否自建 Umami** | 一开始同时维护多套统计 | 一个人先看国内自然搜索、页面和咨询入口点击即可 |

**个人成本原则：** 第一年的钱优先花在“域名、备案服务器、稳定 HTTPS、备份”；不要为所谓 SEO 快速排名购买外链包、采集内容、伪原创工具或昂贵营销套餐。价格随促销变化，以服务商下单页为准。

1. 购买服务器：打开 [阿里云轻量应用服务器](https://www.aliyun.com/product/swas)，选择**中国大陆地域、Ubuntu 24.04、2 核 4 GB、60 GB SSD、5 Mbps**。下单时确认该实例支持备案。

4. 搜索收录：正式域名可访问后，依次进入 [百度搜索资源平台](https://ziyuan.baidu.com/)、[百度统计](https://tongji.baidu.com/) 和 [Bing Webmaster Tools](https://www.bing.com/webmasters/)，验证域名并提交 `https://主域名/sitemap.xml`。

## 2. 上线前必须完成的决策

### 2.1 主域名与 URL 规则

1. 确定一个简短、可读、与个人品牌一致的主域名；本项目固定使用**不带 `www` 的版本**，即 `https://主域名.com`。
2. `https://www.主域名.com` 与 HTTP 版本永久 301 跳转到 `https://主域名.com`。
4. 文章 URL 一经上线尽量不改。改标题可以，改 slug 要做 301 跳转。
5. 域名和服务器备案主体统一使用本人真实信息，减少备案和续费麻烦。

### 2.2 域名最终建议、风险与五个候选

**不建议使用 `lunwendaixie.com`。** 域名本身不必然等于备案违规，但它直接包含“论文代写”，会带来三类现实风险：

1. 备案审核、广告审核、平台内容审核可能要求说明业务，公开站点若与学术不端服务相关，存在被要求整改、停止解析或拒绝合作的风险。
2. 搜索用户和合作平台会把它理解为代写站，降低“研究辅导、方法教学、润色优化”这一长期品牌的信任度；也不利于 B站、视频号、知乎、小红书等公开内容分发。
3. 关键词域名并不是国内搜索排名捷径。搜索排名主要取决于内容质量、收录、访问稳定性和用户行为；把高风险词写进域名，风险远大于可能的点击提示作用。

以下为**优先候选名，不保证此刻仍可注册**；必须在阿里云域名搜索页实时确认可用性。选择原则是：拼音短、含义正面、可覆盖多学科、适合口播与微信名片，而不是堆“代写”词。

| 优先级 | 候选 `.com` | 推荐原因 |
| ---: | --- | --- |
| 1 | `xueshuyanjiu.com` | 覆盖研究方法、选题和多学科内容，品牌边界最稳 |
| 2 | `yanjiufangfa.com` | 与“研究方法、实证分析、文献综述”等高意图内容直接相关 |
| 3 | `xuelunzhinan.com` | 易记，适合面向学生的教程、视频和知识库 |
| 4 | `lunwenfangfa.com` | 明确覆盖论文方法，但不触及代写表述 |
| 5 | `yanjiuxiezuo.com` | 适合写作、文献与润色优化内容集群 |

最终只注册并运营一个主域名。若预算允许，再注册同名 `.cn` 仅做品牌保护，并 301 到 `.com`；不要把两者做成两个可收录网站。

### 2.4 自然流量与微信、QQ 私域转化预测

预测以当前 90 篇学科文章为起点，假设：每周新增或实质更新 2–4 篇文章；每周发布 1 个长视频并拆分短内容；每篇视频和站外内容都链接到对应站内文章；不购买刷量或垃圾外链。搜索收录通常存在 4–12 周滞后，以下为**区间预测而非承诺**。

| 上线阶段 | 月自然搜索访问 | 微信新增联系 | QQ 新增联系 | 有效咨询（两者合计） | 判断依据 |
| --- | ---: | ---: | ---: | --- |
| 第 1 月 | 0–200 | 0–3 | 0–1 | 0–2 | 备案后刚提交收录，主要依赖视频和熟人入口 |
| 第 3 月 | 300–1,200 | 3–18 | 1–7 | 2–16 | 部分长尾词开始收录，专题内容形成内链 |
| 第 6 月 | 1,500–5,000 | 15–70 | 5–25 | 10–60 | 有持续更新、视频导流和文章集群的前提下 |
| 第 12 月 | 5,000–15,000 | 50–220 | 15–80 | 35–180 | 需已有稳定收录、品牌搜索与高质量更新 |

估算漏斗：自然访问 → 联系入口点击约 **0.8%–2.5%**；点击 → 成功添加微信/QQ 约 **35%–65%**；成功添加 → 有效咨询约 **40%–65%**。微信预计占新增私域联系的 **70%–80%**，QQ 占 **20%–30%**。若内容更新停止、文章质量较低或站点不稳定，结果可能低于区间；不要把预测当作收入承诺。

### 2.2 备案与合规边界

1. 购买大陆服务器后，在对应云厂商控制台申请 **个人 ICP 备案**；完成实名、身份核验、域名核验、网站信息提交。
2. 备案通过前不要将正式域名作为公开主站推广；可用本地或临时测试地址验收，但设置为不收录。
3. 备案号下发后，将备案号和工信部链接展示在网站页脚，并按服务商要求完成公安联网备案（如适用）。
4. 你的网站会收集微信、QQ、邮箱等联系方式：隐私说明必须与实际一致；只收集必要信息、不在统计事件中记录联系方式或论文正文、不要把咨询内容发到公开群或日志。
5. 服务说明应清楚写明提供学习辅导、研究方法教学、修改建议与润色优化等服务内容。

## 4. 服务器首次配置

以下命令在服务器 SSH 终端执行。命令中的 `YOUR_USER`、`YOUR_DOMAIN`、`YOUR_REPO` 必须替换为你的实际值。

### 4.1 登录并创建普通部署用户

```bash
ssh root@服务器公网IP
apt update && apt upgrade -y
adduser deploy
usermod -aG sudo deploy
su - deploy
```

后续日常部署使用 `deploy` 用户，不长期使用 root。云防火墙只放行 `80`、`443` 和个人固定 IP 的 `22` 端口；关闭不需要的端口。

### 4.2 安装基础软件、Node 与 Yarn

```bash
sudo apt install -y git nginx curl build-essential
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
corepack enable
corepack prepare yarn@3.6.1 --activate
node -v
yarn -v
```

本项目的 `package.json` 已声明 `yarn@3.6.1`，部署时使用 Yarn，不要混用 npm 安装依赖。

### 4.3 拉取项目并配置环境变量

```bash
sudo mkdir -p /var/www/paper-site
sudo chown -R deploy:deploy /var/www/paper-site
cd /var/www/paper-site
git clone YOUR_REPO .
cp .env.example .env.local  # 若仓库没有该文件，则新建 .env.local
nano .env.local
```

至少确认以下配置（名称以项目实际环境变量为准）：

```bash
NEXT_PUBLIC_SITE_URL=https://YOUR_DOMAIN
```

不要把 API 密钥、统计 token、邮件密码、微信/QQ 私密信息提交到 Git。`.env.local` 只保存在服务器和个人加密备份中。

### 4.4 首次构建与启动

```bash
cd /var/www/paper-site
yarn install --immutable
yarn typecheck
yarn lint
yarn build
yarn serve
```

确认本机 `http://127.0.0.1:3000` 能访问后，按 `Ctrl + C` 停止临时服务，再交给 PM2 常驻。

## 5. 用 PM2 常驻运行（低维护）

```bash
sudo npm install -g pm2
cd /var/www/paper-site
pm2 start yarn --name paper-site -- serve
pm2 save
pm2 startup systemd -u deploy --hp /home/deploy
```

执行最后一条后，PM2 会提示一条需要 `sudo` 执行的命令；复制执行一次即可。日常检查只需：

```bash
pm2 status
pm2 logs paper-site --lines 100
```

## 6. Nginx 与 HTTPS 配置

### 6.1 Nginx 反向代理

创建 `/etc/nginx/sites-available/paper-site`：

```nginx
server {
    listen 80;
    server_name YOUR_DOMAIN www.YOUR_DOMAIN;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用并检查：

```bash
sudo ln -s /etc/nginx/sites-available/paper-site /etc/nginx/sites-enabled/paper-site
sudo nginx -t
sudo systemctl reload nginx
```

在 DNS 中把主域名和 `www` 的 A 记录指向服务器公网 IP。DNS 生效后再申请证书。

### 6.2 免费 HTTPS 与强制跳转

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d YOUR_DOMAIN -d www.YOUR_DOMAIN
sudo certbot renew --dry-run
```

Certbot 会协助配置 HTTPS 跳转。随后在 Nginx 中明确让 `www.YOUR_DOMAIN` 301 跳转到 `https://YOUR_DOMAIN`，避免两个版本同时被收录。完成后检查：

```bash
curl -I http://YOUR_DOMAIN
curl -I https://YOUR_DOMAIN
curl -I https://YOUR_DOMAIN/sitemap.xml
curl -I https://YOUR_DOMAIN/robots.txt
```

要求：HTTP 自动跳转 HTTPS；非主域名自动跳转主域名；`sitemap.xml` 与 `robots.txt` 返回 `200`。

## 7. 国内 SEO 上线清单（最重要）

### 7.1 必做技术项

- [ ] `NEXT_PUBLIC_SITE_URL` 替换为正式 HTTPS 主域名后重新构建。
- [ ] 首页、学科页、所有文章页均可返回 `200`，无登录墙、验证码墙或地区拦截。
- [ ] `https://主域名/sitemap.xml` 包含全部学科与文章 URL。
- [ ] `https://主域名/robots.txt` 不屏蔽公开文章、学科页、sitemap。
- [ ] 每篇文章有唯一 `<title>`、`meta description`、canonical、发布日期/更新时间和 Article 结构化数据。
- [ ] 文章之间至少有 2–4 个语义相关内链；不要只把所有链接指向首页。
- [ ] 移动端首屏可读、图片压缩、无大体积自动播放视频。
- [ ] 404 页面返回真正的 404；过期文章如需迁移，做 301，不要全部跳首页。

### 7.2 国内站长平台动作

1. 注册并验证 **百度搜索资源平台**，优先验证整个主域名。
2. 提交正式 sitemap URL，并在新文章发布后主动提交新 URL。
3. 注册 **Bing Webmaster Tools**，提交同一个 sitemap。
4. 360、搜狗、微信搜一搜以自然发现和站外内容入口为主；若其站长入口可用，再按平台当前指引验证并提交，不要为提交动作反复变更网站结构。
5. 任何平台发现抓取异常，先检查 `robots.txt`、HTTP 状态码、canonical、服务器日志和页面是否可被未登录访客访问。

### 7.3 内容策略：比“堆 SEO 词”更有效

每篇文章只解决一个明确问题。标题优先覆盖学生的自然搜索表达：

- “教育学论文访谈怎么做：访谈提纲、样本与编码分析”
- “法学论文案例分析怎么写：事实、争点与裁判理由”
- “Stata 固定效应模型怎么选：个体、时间与双向固定效应”
- “文学论文文本细读怎么写：引文证据与理论解释”

建议每周只新增 **2–4 篇**真正有深度的文章，并同步录制 1 个长视频、拆出短视频。视频简介链接到对应文章页，不要全部导向首页。稳定更新六个月比一次性发布大量近似内容更有利于收录和信任。

## 8. 统计、转化与隐私

### 最低可行统计方案

1. 接入百度统计，重点查看：自然搜索来源、搜索词、落地页、地区、移动端比例。
2. Umami 可后置部署；先用百度统计已经足够。需要更细的隐私可控数据时，再部署 Umami。
3. 只跟踪匿名事件，例如：文章阅读、学科切换、二维码查看、微信号复制、咨询按钮点击。
4. 不把微信号、QQ 号、邮箱、论文标题、全文、附件内容传入统计系统。

### 每周只看四个指标

| 指标 | 用途 | 行动 |
| --- | --- | --- |
| 百度自然搜索点击 | 判断收录与排名是否增长 | 找增长最快的主题继续扩展 |
| 自然搜索落地页 | 判断用户真正搜索什么 | 给高流量文章补内链与明确咨询入口 |
| 文章阅读/停留 | 判断内容是否解决问题 | 优化开头、目录、表格和案例 |
| 咨询按钮/微信复制 | 判断转化 | 调整页面 CTA，不急于增加更多表单字段 |

```bash
yarn install --immutable
yarn typecheck && yarn lint && yarn build
pm2 reload paper-site --update-env
curl -I https://YOUR_DOMAIN/sitemap.xml
```

发布后抽查首页、一个学科页、一篇新文章、咨询页和手机端；再向百度提交新增文章 URL。

### 出问题时的回滚

```bash
cd /var/www/paper-site

yarn install --immutable

```

确认恢复后，再在本地修复问题。不要在服务器上直接修改业务代码；服务器只用于部署。

## 10. 备份与维护：一个人也能坚持

### 每周 20 分钟

- 查看 PM2 是否在线、Nginx 证书是否正常。
- 查看百度统计中自然搜索与高访问文章。
- 发布 2–4 篇文章或更新 1–2 篇旧文章。
- 提交新 URL，检查是否有抓取错误。

### 每月 30 分钟

- 更新系统安全补丁：`sudo apt update && sudo apt upgrade -y`。
- 检查磁盘：`df -h`；检查日志：`pm2 logs paper-site --lines 100`。
- 备份 `.env.local`、Nginx 配置和数据库/咨询数据（如后续接入）。
- 在另一台设备上验证 GitHub 仓库、域名账户和服务器账户均可登录。

### 必须保留的三份副本

1. GitHub 代码仓库。
2. 云服务器运行版本。
3. 本地或加密云盘中的 `.env.local`、域名/DNS/Nginx 配置和咨询数据导出。

## 11. 不建议做的事

- 不把 Vercel、GitHub Pages、Cloudflare Pages 作为面向国内学生的唯一正式主站。
- 不为“快速收录”购买采集文章、群发外链、隐藏文字、关键词堆砌或刷点击服务。
- 不把 90 篇文章都复制到多个平台全文发布；站外平台应发布摘要、视频和独立观点，链接回站内原文。
- 不频繁更换域名、URL 结构、文章分类和主域名版本。
- 不一开始部署 Docker、Kubernetes、复杂监控集群或多台服务器；有稳定日均访问和明确瓶颈后再升级。

## 12. 发布前仍需完成的项目优化与 Git 策略

### 12.1 上线前必须补齐的优化

以下项目比继续增加服务器配置更重要，应在正式提交百度收录前完成：

| 优先级 | 优化项 | 原因与验收方式 |
| ---: | --- | --- |
| P0 | 将 `siteMetadata.siteUrl` 与 `NEXT_PUBLIC_SITE_URL` 改为正式不带 `www` 的 HTTPS 域名 | 构建后检查所有 canonical、sitemap、JSON-LD 不再出现 localhost 或示例域名 |
| P0 | 为“研究议题、方法路径、质量标准”补充独立可抓取 URL | `#section-1` 这类哈希不会形成独立服务端页面；建议后续增加 `/disciplines/education/research`、`/methods`、`/standards` 等静态页，各自有 title、description 和内部链接，利于国内搜索收录 |
| P0 | 检查 `scripts/submit-baidu.mjs` 是否包含全部 90 篇文科学科文章 | 站内 sitemap 已有文章不代表主动推送脚本一定覆盖；需用正式域名跑一次并核对 URL 数量 |
| P0 | 配置咨询入口事件而非表单事件 | 只记录“微信复制、QQ复制、二维码查看、咨询页访问”等匿名事件；确认没有在线表单 API 和联系人数据落库 |
| P1 | 压缩二维码与后续文章配图，使用 WebP/AVIF | 保持移动网络首屏加载快；图片需保留描述性 alt 文本 |
| P1 | 为每篇文章补充 2–4 个相关推荐链接 | 形成学科主题集群，让搜索爬虫和读者能继续阅读 |
| P1 | 增加真实的作者页、更新政策与内容校验说明 | 提升专业信任；不虚构学历、案例或服务成果 |
| P2 | 当日均访问稳定超过 1,000 再评估 CDN、图床和 Umami | 数据量与性能需求达到阈值后再增加维护负担 |

### 12.2 是否要新切发布分支

**建议切一个短期发布分支，但不要长期维护“生产分支”。** 推荐流程：

```text
main（持续开发、已通过本地测试）
  └── release/production-v1（上线前冻结、只修 P0/P1 问题）
          └── 打标签 v1.0.0（服务器只部署这个已验证版本）
```

具体操作：

```bash
git switch main
git pull --ff-only
git switch -c release/production-v1
# 完成 P0 项、构建、浏览器验收
git add .
git commit -m "chore: prepare production release v1.0.0"
git tag -a v1.0.0 -m "first production release"
git push origin release/production-v1 --tags
```

服务器上线时检出标签而不是“最新 main”：

```bash
git fetch --tags
git checkout v1.0.0
yarn install --immutable && yarn build
pm2 reload paper-site --update-env
```

上线验证无误后，将发布分支合回 `main`，以后每次正式发布建立 `v1.0.1`、`v1.1.0` 等标签。这样仍然只有一个长期开发主线，不会给个人维护增加分支同步负担，同时可精确回滚。
